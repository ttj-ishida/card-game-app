### 4.2 game-core の import 指定子

- `packages/game-core/src/` の source-to-source import と `index.ts` の re-export は **`.ts` 指定子**（`allowImportingTsExtensions: true` を game-core と apps/mobile 両 tsconfig に設定済み）。
- `index.ts` は薄いバレル（`export * from "./core.ts"` 他）。ルールエンジン本体は `core.ts`（~1100行）。
- 一方向 DAG：`index.ts` → {`core.ts`, 6モジュール}；各モジュール → {`core.ts`, 兄弟}；`core.ts` → 相対 import なし。
- `apps/mobile/metro.config.js` に残るシムは `@card-game-app/ui`（`packages/ui/src/index.ts` が `./tokens.js` を re-export）用のみ。game-core のシムは M3 sub-1 で削除済み。

### 4.3 決定論・RNG

- game-core は純粋・同期。1局は `seed` からバイト再現可能。`createRng(seed)`（mulberry32）→ 配布用に1回 `fork()` → 手番ごとに1回 `fork()`（`turnLog.length` で index）。
- `enumerateLegalPlays(state, options?)`：`options` 省略時は数字手 + PASS のみ（現行と byte 一致）。`{ includeSkills: true }` でスキル手も列挙（JOKER_CLEAR / JOKER_TRANSFORM（`JOKER_TRANSFORM_CANDIDATE_CAP = 2000`）/ EXTENSION_SEAL / REVOLUTION）。
- カード保存則：`Σ 実カード（transformedFromSkillId === undefined）in hands + discardPile + activeField === 36`。変化Joker（`JOKER_AS_<skillId>`）は 36 に含めない。`roundLoop.ts` と `apps/mobile/src/state/cpuGameStore.ts` の両方で assert。

### 4.4 1手番のスキルは1枚（JOKER-003）

- 各プレイヤーのスキルカードは最大1枚。1回の `resolvePlay` で作られる変化Joker は最大1つ。
- M3 sub-3 で `resolveCardPlay` にガード追加：`useSkill:'JOKER_TRANSFORM'` はちょうど1宣言・`skillId` が保有スキル一致、他 `useSkill` で宣言があれば拒否。新 reason `INVALID_JOKER_DECLARATION`。
- 低レベル関数 `evaluateJokerTransformPlay` は複数宣言対応のまま（`joker.test.ts` でカバー）。ガードは game-action 層（`resolveCardPlay`）のみ。
- **T-RULE-017**（必須§31.2「2枚のJokerが別の数字＋属性を宣言→組み合わせ成立すれば合法」）は `ruleAcceptance.test.ts` で **2ターン経路**（P2がリードで変化Jokerを含む SEQUENCE → P1が自分の変化Jokerで拡張）としてテスト。

### 4.5 apps/mobile の純モジュール規律

- `apps/mobile/src/features/cpu-game/*.ts`（純ロジック）は `fetch` / `AsyncStorage` / `Date` / `Math.random` を直接 import しない。全て DI ポート経由（`configureCpuGameStore(deps)` で `makeSeed`/`makeId`/`now`/`storage`/`http`/`supabaseUrl`/`anonKey` を注入。ネイティブ配線は `cpuGameAdapters.ts`）。
