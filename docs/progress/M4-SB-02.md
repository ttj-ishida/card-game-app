# M4-SB-02: `round_hands`、`round_skills`を所有者別に作る

状態: 完了
日付: 2026-09-04

## 概要

M4オンライン対局の非公開情報として、本人手札と本人スキルを所有者別に保存するテーブルを追加した。

M3までの`players`は端末生成の匿名IDだけなので、M4オンラインでは`round_players.auth_user_id`をSupabase Authの本人判定キーとして追加した。RLSは`auth.uid()`と`round_players.auth_user_id`を照合し、本人の`round_hands` / `round_skills`だけをSELECTできるようにする。

## 実装

- `supabase/migrations/20260904093000_create_online_private_cards.sql`
  - `room_players.auth_user_id`
    - 待機室での本人判定用。CPU席は`null`を許容する。
  - `round_players.auth_user_id`
    - 対局中の本人判定用。CPU席は`null`を許容する。
  - `round_hands`
    - `round_id`、`player_id`、`card_id`、`position`、`card_state`を保持。
    - `(round_id, player_id, card_id)`を主キーにする。
  - `round_skills`
    - `round_id`、`player_id`、`skill_id`、`used`、`consumed_at`を保持。
    - 1対局1プレイヤーにつき1スキルに制限する。
  - `public.is_round_player_owner(round_id, player_id)`
    - RLSから呼ぶ本人判定用の`security definer`関数。
  - `round_hands_select_owner` / `round_skills_select_owner`
    - authenticated本人だけSELECT可能。
    - anonはSELECT不可、authenticatedのINSERT/UPDATEも不可、service_roleは全権限。
- `supabase/tests/online_private_cards_schema.sql`
  - 列、型、既定値、RLS、制約、本人手札・スキルの保存を確認。
- `supabase/tests/online_private_cards_access.sql`
  - プレイヤー1が自分の手札・スキルだけ見えること、プレイヤー2が自分の行だけ見えること、anonとauthenticatedの直書きが拒否されることを確認。
