## メモ

- **ヒューリスティックは最小版**：`standardPolicy` のスキル発動ロジックは設計書 §6 の決定的順序（枚数・スキル有無・宣言内容・結果強度）に従い、上がり > 空場リード > 応答 > 本来パス時スキル > PASS の優先順で実装。QA-01 の 1000 局で全 4 スキル（`JOKER_CLEAR` / `JOKER_TRANSFORM` / `EXTENSION_SEAL` / `REVOLUTION`）発動を確認済み。変化Joker上がり 0 件、停止（runaway loop）0 件。

- **ヒューリスティック調整は後続**：発動頻度（JOKER_TRANSFORM は低頻度 100/1000 局のみ。現仕様「数字だけでは作れない組み合わせ完成 + 手札を多く減らす」）と手番数分布をもとに、設計書 §11 の申し送りどおり M3 の次段階で微調整。

- **`core.ts` 分割**：`git mv packages/game-core/src/index.ts packages/game-core/src/core.ts` → 新 `index.ts` がバレル（再エクスポート 7 行）。M2 の 6 ソースファイル（`rng.ts` / `deal.ts` / `legalMoves.ts` / `cpuPolicy.ts` / `cpuPolicyStandard.ts` / `roundLoop.ts`）の import を `.ts` 拡張子へ統一（相対 import → 兄弟同じ層）。循環 import 制約が消滅し、TDZ 違反リスク消失。`.test.ts` は `from "./index.ts"` のまま（バレル経由で全解決）。

- **metro シム削除**：`apps/mobile/metro.config.js` の `gameCoreSrc` を使う分岐を削除。`tsconfig` に `allowImportingTsExtensions: true` を追加して `.ts` 指定子を解決可能にしたため。`npm run mobile:typecheck` / `tsx` / Metro すべて `.ts` を通す（probe 済み）。`@card-game-app/ui` の `uiTokensEntry` シム分岐は残置（別 TODO）。

- **実カード判定**：`const isRealCard = (c: NumberCard) => c.transformedFromSkillId === undefined;` を `roundLoop.ts::assertInvariants` へ導入。カード保存則は「実カードのみ 36 枚」（変化Joker由来カードは 36 に含まない）。同じロジックを `apps/mobile/src/state/cpuGameStore.ts::assertCardConservation` へ適用。M3 でスキル手が出るようになり、変化Joker が場／捨札に出るが、保存則は一貫性を保つ。

- **人間のスキル UI**：Joker 宣言画面・封印／革命トグル実装は M3-EX-01 / M3-EX-02（`legalPlaysForHuman` は本タスク内で `includeSkills` を指定しないため、人間の手番では数字手のみが候補に出る）。

## 対応した設計要件

- §3 `core.ts` 分割（循環 import 制約と metro シム除去）
- §4 カード保存則の修正（`isRealCard` で変化Joker除外）
