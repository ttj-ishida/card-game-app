# M4-ARC-01: サーバー権威方式の技術スパイクを行う

状態: 完了
日付: 2026-09-04

## 概要

2～6人のフレンド対戦を、招待リンクから参加し、複数端末で同期・再接続しながら1局完走できる状態へ進めるため、オンライン対戦の権威をどこに置くかを比較した。

採用案は、Edge Function + 共有TypeScriptルール + Postgresの条件付きDB更新とする。クライアントは表示と入力を担当し、カード提出、パス、スキル使用、退出、再接続、CPU引継ぎの確定はサーバー側で行う。

## 決定

- Edge Function + 共有TSルール + 条件付きDB更新を採用する。
- クライアント権威方式は、手札偽装、二重消費、端末間不一致を防ぎにくいため不採用とする。
- Postgres関数中心方式は、既存TypeScriptルールとの二重実装が重いため不採用とする。
- 専用ゲームサーバーは、M4の範囲では運用費と実装量が大きいため不採用とする。
