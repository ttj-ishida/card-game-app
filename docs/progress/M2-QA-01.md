## 概要

Task 5（`playRound` エンジン）に基づき、CPU 自動対戦の安定性を検証するテストハーネス `cpuSelfPlay.test.ts` を実装した。

`playRound` は内部で以下を保証する:
- **不変条件の毎手検査** — カード総数 36 / cardId 一意性 / 手番席の検証。違反時は throw。
- **上限チェック** — `maxTurns` 1000 で停止（無限ループ防止）。
- **決定性** — RNG 消費を固定化（同一 seed → バイト一致）。

ハーネスは固定 seed 群を用いて `playRound` を 2～6 人規模で複数回実行し、上記の保証を検証する + 追加チェック:

1. 全試行が `stopReason: "WINNER"` に到達（対局が決着する）
2. 宣言された勝者が実際に手札 0 枚（有効な勝者判定）
3. `turns.length < 500` で有界性を追加確認（`maxTurns` 1000 の実測検証）
4. 複数 seed で `playRound` 実行を 2 回ずつ、結果が完全一致（決定性の再保証）

## メモ

### Task 5（`playRound`）の役割

- **不変条件の保証** — `resolvePlay` 後、カード総数 36 / cardId 一意性 / 手番席の検査。違反時は throw。
- **上限による停止** — `maxTurns` 1000 に達すると停止（ただしデフォルトは呼び出し側で設定）。
- **決定性エンジン** — RNG 消費を固定化。同一 seed → バイト一致の `RoundResult`。

### このハーネスの役割

- **安全性の統計検証** — 120 試行で WINNER 到達・勝者妥当性を確認。スロー発生なし。
- **実測の有界性チェック** — `< 500` アサートで上限内を追加確認。
- **決定性の再検証** — 複数 seed 組で 2 回実行、結果の完全一致を確認。
- **統計ログ出力** — 手番数分布（min/max/mean）を実測値で記録。失敗時に絶対 seed + 理由を記録。
