## 概要

36枚の数字カードデッキと6枚のスキルカードデッキを定義し、プレイヤー人数に応じた配布枚数（2人18枚、3人12枚、4人9枚、5人8+7x4枚、6人6枚）と先攻位置を決定する関数 `dealRound()` を実装した。5人専用の8枚席は初局は乱数で、再戦は基準先攻位置から時計回りにローテーション。手札はランク昇順、同ランクは定義順のスーツ順でソート。すべては `Rng` による決定的な乱数で駆動される。

## インターフェース

- `NUMBER_DECK: readonly NumberCard[]` — 36枚の数字カード（ランク×スーツ組み合わせ）
- `SKILL_DECK: readonly SkillCard[]` — 6枚のスキルカード（Joker Hero/Saint、Extension Seal ×2、Revolution ×2）
- `dealRound(input: DealInput): DealResult`
  - `DealInput`: `{ playerIds: readonly string[]; rng: Rng; rematchIndex?: number; baselineFirstPlayerId?: string }`
  - `DealResult`: `{ players: PlayerState[]; firstPlayerId: string; dayNight: "DAY"; eightCardSeatId: string | null }`
- 乱数消費順序（固定仕様）: `shuffle(numbers)` → `shuffle(skills)` → （5人初局のみ）`nextInt(5)` → （5人以外初局のみ）`nextInt(n)`

## メモ

- 循環依存を避けるため、`deal.ts` 内で `RANK_CODES`、`SUIT_CODES`、および一部のファクトリ関数（`createNumberCard`、`createSkillCard`、`rankNumber`、`createPlayerState`）を重複定義した。これは index.ts との import 順序がモジュール初期化時に競合するのを防ぐため。
- 再戦時の先攻ローテーション（5人専用8枚席を含む）は呼び出し側が `baselineFirstPlayerId` と `rematchIndex` を管理し、`dealRound()` はそれに基づいて座席を計算する。
- 手札の並べ順は `rankNumber()` による昇順が基準。同ランク内では `SUIT_CODES` の定義順（FIRE → WATER → WIND → EARTH）。
- `dayNight` は常に初期値 `"DAY"`。
- 人数チェック（2～6人）、プレイヤーID の一意性、再戦時の基準先攻の存在確認を実装。
