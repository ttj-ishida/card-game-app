## 概要

アクティブプレイヤーの手札から合法手をすべて列挙する `enumerateLegalPlays(state)` を実装した。候補となる cardId 集合（単体 / 同数2〜4枚 / 連番3〜9枚の属性組み合わせ）を生成し、それぞれを `resolvePlay` のドライランに通して `ok` を返すものだけを残す。`resolvePlay` がパスを受理する場合は末尾に `PASS` エントリを追加する。返り値は決定的な順序（actionKind → 枚数昇順 → 結果の組み合わせの強さ昇順 → cardIds 結合文字列の辞書順、PASS は常に末尾）にソートされる。あわせて `index.ts` の `combinationStrength` を private から export に格上げし、ポリシー側（Task 4）と共有する薄いエイリアス `resultStrength` を追加した。

## インターフェース

- `type LegalPlay = { input: PlayInput; actionKind: PlayActionKind | "PASS"; resultingCombination: NumberCombination | null; goesOut: boolean }`
- `function enumerateLegalPlays(state: RoundState): LegalPlay[]`
  - `state.winnerId` が設定済み、またはアクティブプレイヤーが見つからない場合は `[]` を返す。
  - `goesOut` は着手後の手札枚数が 0 かどうかで判定（`resolvePlay` の結果状態から算出）。
- `function resultStrength(combination: NumberCombination, dayNight: DayNight): number` — `combinationStrength` のエイリアス。

## メモ

- 合法判定は `resolvePlay` のドライランに一元化。列挙器の責務は候補生成と決定的ソートのみ。ルールロジック（ロック、昼夜、拡張封印、シェイプ一致など）は一切複製していない。
- `combinationStrength` を private → export に格上げ（本体不変の追加的変更）。循環 import を避けるため `index.ts` から取り込む値（`resolvePlay` / `combinationStrength` / `rankNumber`）は関数本体内でのみ参照し、`legalMoves.ts` のモジュールトップレベルでは使用していない。
- 候補 cardId 集合はソート済み結合キーで重複排除する。同一カード集合を異なる経路で生成しても列挙は1回のみ。
- 連番候補は属性の組み合わせ爆発を避けるため積が 512 を超える窓をスキップする（上限ガード）。
