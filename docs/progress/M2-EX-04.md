## 概要

CPU 戦の人数選択画面を実装。`/cpu-game/setup` ルートで「人数を選ぶ」→「開始」で対局をスタート。matchConfig モジュール（人数 2～6、seat-0 が人間、残り CPU）を設定し、`cpuGameStore.startMatch(totalPlayers)` を呼んで `/cpu-game/play` へ遷移。

## メモ

- **matchConfig の職責** — 人数から席配置（seat-0=HUMAN、seat-1..=CPU STANDARD）を生成。M2 は常に 1 人間。M4 で「複数人間（リモート）」を足すときは `SeatConfig.kind` に 'REMOTE_HUMAN' を追加するだけ。
- **packId の固定化** — M2 は `packId='DEFAULT'` 固定（数字 + 属性ラベル描画）。M3-EX-08（ソロ設定）/ M4（卓設定）でユーザー選択へ拡張。
- **画面は薄い皮** — setup.tsx は「人数選択 UI + startMatch 呼び出し」のみ。ロジックは matchConfig で完結。
- **M4 への継ぎ目** — `buildMatchConfig()` の内部が「seat-0 固定 HUMAN」の仮実装なので、M4 で引数パターンを拡張（`config: { humanSeatIds: ['seat-0', 'seat-3'] }` など）する対応可。

## テーブル

### matchConfig テスト

| テスト | 対象 | 検証内容 |
| --- | --- | --- |
| `isValidTotalPlayers` | 入力値 | 整数かつ 2..6 → true、外は false |
| `buildMatchConfig` | 出力形状 | seat 数 = 入力人数、seat-0=HUMAN、残り=CPU STANDARD |
| `seatPolicies` | CPU 席のみ抽出 | STANDARD ポリシー |
| `humanSeatIds` | 人間席抽出 | M2 は常に `['seat-0']` |
| `isHumanSeat` | 判定 | seat-0 のみ true |
