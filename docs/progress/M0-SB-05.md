## 実施内容

- 公開マスタ4テーブルの読取権限と管理更新権限を分離した。
- `anon`と`authenticated`には`SELECT`のみを付与した。
- `anon`と`authenticated`から`INSERT`、`UPDATE`、`DELETE`権限を明示的に剥がした。
- `service_role`へ管理更新用の`ALL`権限を付与した。
- 4マスタそれぞれに公開読取用のRLS SELECT policyを作成した。
- 書込用RLS policyは作成せず、一般クライアントが直接更新できない状態にした。
- pgTAPでポリシー数、権限、一般ロールでの読取件数を検査した。

## 補足

- `service_role`はサーバー側専用として扱い、クライアントへ配布しない。
- 管理画面や運営者ロールの詳細は未定義のため、M0-SB-05ではサーバー専用権限への分離までを範囲とした。
- Supabase CLIのDBテストを並列実行すると、ローカルtelemetryファイル更新が競合する場合があるため、テストは順番に実行する。
