# M4-EX-05 プレイ要求、受付中、成立、不成立のUI

## Status

Done（MVP）。関連する M4-EX-06/07/08/09/GR-02 の一部を同じ作業で前進させた（詳細は Follow-up）。

## Summary

- `apps/mobile/src/state/onlineRoundStore.ts` を追加。対局スナップショットの取得（`start`/`poll`）、カード選択、プレイ/パスの送信、対局からの退出を担う zustand/vanilla ストア。サーバーの `state_version`/`event_seq` を単一の真実として、送信成功後は必ず `poll()` で権威状態を取り直す。
- `apps/mobile/src/features/online-room/onlineLegalMoves.ts` を追加。対局スナップショット（自分の手札・保有スキルのみ判明、相手はプレースホルダー空手札）から `enumerateLegalPlays`（既存の `packages/game-core`）を使って自分の手番のときだけ合法手を計算する。これにより CPU 戦と同じ手札選択・提出可否ロジック（`handSelection.ts`/`skillPlayOptions.ts`）を再利用できる。
- `apps/mobile/src/features/online-room/onlineRoomClient.ts` に `leaveOnlineRound`（`leave_friend_round` RPC）を追加。
- `apps/mobile/src/app/online-room/play.tsx` を追加。手札・場・相手の枚数・ターン表示・履歴パネル・スキル（JOKER_CLEAR/EXTENSION_SEAL/REVOLUTION の3種、変化Jokerの数字・属性宣言は未対応）・勝敗バナー・退出確認を持つオンライン対局画面。2秒間隔のポーリングで同期する。
- `online-room/lobby.tsx`: 対局成立（`status === 'started'`）で `onlineRoundStore.start(roundId)` を呼び、対局画面へ自動遷移するようにした。
- `_layout.tsx` / `cpuGameAdapters.ts`: ルート登録とストア配線（`onlineRoundDeps()`）を追加。

## Follow-up（既知の未完了・簡略化点）

- **M4-EX-06（Realtimeイベントの順序・欠落検知）**: Realtime購読は未実装。2秒ポーリング＋`state_version`/`event_seq`による差分取得で代替。取りこぼし検知の明示UIは無い。
- **M4-EX-07（切断表示と60秒以内の自動再接続）**: ポーリング失敗時に `connection: 'reconnecting'` バナーを出し、次のポーリングで自動復帰する簡易実装。60秒の期限管理・指数バックオフは未実装。
- **M4-EX-08（オンライン結果と再戦意思確認）**: 対局画面内に簡易勝敗バナー（ロビーへ戻る/ホームへ）のみ。専用の結果画面・再戦フローは未実装。
- **M4-EX-09（退出・CPU引継ぎ表示）**: `leave_friend_round` を呼ぶ退出ボタンとハードウェア戻るキーの確認ダイアログのみ。CPU引継ぎ後の見た目上の表示（「CPUが操作中」等）は無い。
- **M4-GR-02（通信中・再接続中・同期失敗の表示素材）**: 文言のみ、専用のグラフィック素材は無い。
- **変化Joker（JOKER_TRANSFORM）**: 数字・属性の宣言UIが無いため、オンライン対局では JOKER_CLEAR（場流し）のみ対応。宣言を伴う変化は次イテレーションで対応する。
- **既知のサーバー側の制約（新規発見、今回は変更していない）**: `submit-play` Edge Function は毎リクエストで `RoundState` を作り直しており、ラウンド跨ぎの連続パス数（`consecutivePasses`）を永続化していない。3人以上の対局でパスによる場流しタイミングがズレる可能性がある。M4-QA-01〜03（複数クライアント自動操作・遅延/切断注入・50局連続）で顕在化しうるため、着手時に要修正。
- **イベントpayloadのキー不一致（新規発見）**: `submit-play` の勝者通知は `winner_id`、`leave_friend_round` は `winner_player_id` と異なるキー名を使っている。クライアント側 (`onlineRoundStore.extractWinnerId`) は両対応済みだが、サーバー側で揃えるのが望ましい。
