## 実装内容

- `packages/game-core/src/serverRequest.ts` を追加し、サーバー側のプレイ要求検証入口を定義した。
  - `expectedStateVersion` が現在の `stateVersion` と一致しない要求を `STALE_STATE_VERSION` として拒否する。
  - アクティブプレイヤー以外の要求を `NOT_ACTIVE_PLAYER` として拒否する。
  - カード・パス・スキルの合法性は既存の共有ルール `resolvePlay` で判定する。
- `supabase/functions/submit-play` を追加した。
  - Bearer token で認証ユーザーを確認する。
  - service role key でオンライン対局の公開状態、席、本人を含む全席手札、スキルを読み、共有ルール用のスナップショットを組み立てる。
  - このTODOでは M4-SB-07/08 前段として、DB更新は行わず `dry_run: true` の検証結果を返す。
- `scripts/check-m4-edge-function-config.mjs` を更新し、`m4-rule-smoke` と `submit-play` の両方が共有ルール入口を参照していることを検査する。

## 代表ケース

- 正常系: アクティブプレイヤーが現在の状態版で合法手を提出すると `ok: true` になる。
- 状態版不一致: `STALE_STATE_VERSION` で拒否する。
- 手番外: `NOT_ACTIVE_PLAYER` で拒否する。
- 不正手: `resolvePlay` の理由を返す。
- 未認証: Edge Function 側で `UNAUTHENTICATED` を返す。
