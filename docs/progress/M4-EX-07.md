# M4-EX-07 切断表示と60秒以内の自動再接続

## Status

Done（MVP）。M4-EX-06（イベント欠落検知）を同じ実装で対応。

## Summary

`apps/mobile/src/state/onlineRoundStore.ts` のポーリング層を拡張:

- `connection` に `'offline'` を追加。ポーリング/送信の通信失敗が続き、最初の失敗から
  `RECONNECT_WINDOW_MS`（60秒）を超えても復帰できなければ `'offline'` へ落とす。
  それまでは `'reconnecting'` のまま2秒間隔のポーリングで自動再接続を試み続ける。
- `reconnect()` アクションを追加。`'offline'` からの手動再接続。`needsFullResync` を立てて
  `get_friend_round_snapshot` を全件（`after_state_version: null`）で取り直す。
- `connectionAfterFailure(reconnectSinceMs, now)` で失敗時の分類を一元化。`start` 成功時と
  各スナップショット適用時に `reconnectSinceMs` はクリアされる。
- 画面 `apps/mobile/src/app/online-room/play.tsx`:
  - ポーリング用 `setInterval` を `connection === 'offline'` でも停止するよう更新。
  - `'offline'` のとき「接続できません · 再接続」ボタンを表示し `reconnect()` を呼ぶ。

### M4-EX-06（Realtimeイベントの順序・欠落検知）について

`get_friend_round_snapshot` は `after_state_version` より後のイベントを全件返す設計で、
`event_seq` と `state_version` が1:1で進むため通常は欠番が生じない。念のため
`hasEventGap(eventLog, latestEventSeq)` で「手元の最大 < サーバーの latest_event_seq」または
「連番が飛んでいる」を検知したら `needsFullResync` を立て、次のポーリングで全件取り直す。
Realtime購読（WebSocket）自体は未導入 — 2秒ポーリングで代替している。
