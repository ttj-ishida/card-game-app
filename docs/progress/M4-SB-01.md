# M4-SB-01: `rooms`、`room_players`、`rounds`、`round_players`を作る

状態: 完了
日付: 2026-09-04

## 概要

M4フレンド対戦の最初のDB土台として、ルーム、ルーム参加者、対局、対局席を保存できるようにした。

M4-ARC-01のサーバー権威方式に合わせ、この段階ではクライアント直アクセスを開けず、Edge Function/service_roleからの作成・更新を前提にする。招待参加、本人別読取、Realtime配信のRLSはM4-SB-04、M4-SB-09以降で用途に合わせて開ける。

## 実装

- `supabase/migrations/20260904090000_create_online_rooms_and_rounds.sql`
  - `rooms`
    - 招待コード、ホスト、状態、最大人数、ターン秒数、CPU引継ぎ可否を保持。
  - `room_players`
    - ルーム内の参加者、席番号、役割、待機状態を保持。
  - `rounds`
    - ルーム内の1局、ルールセット、参加人数、`state_version`を保持。
  - `round_players`
    - 対局開始時点の参加席、人間/CPU、勝者、終了順を保持。
  - 各テーブルで主キー、外部キー、CHECK制約、一意制約、索引、RLS有効化、service_role権限を設定。
- `supabase/tests/online_rooms_schema.sql`
  - テーブル、列、型、既定値、RLS、制約、ルームと1局の参加席保存を確認。
- `supabase/tests/online_rooms_access.sql`
  - anonが直アクセスできず、service_roleが作成できる権限を持つことを確認。
