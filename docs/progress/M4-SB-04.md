# M4-SB-04: ルーム作成・参加・退出のサーバー処理を作る

状態: 完了
日付: 2026-09-04

## 概要

M4フレンド対戦の待機室ライフサイクルとして、ルーム作成、招待コード参加、退出をRPCで実行できるようにした。

M4-ARC-01のサーバー権威方式に従い、クライアントはテーブルへ直接INSERT/UPDATEしない。authenticatedユーザーはRPCを呼び、RPC内の`security definer`処理が`players`、`rooms`、`room_players`をトランザクション内で更新する。

## 実装

- `supabase/migrations/20260904103000_create_friend_room_lifecycle_functions.sql`
  - `ensure_online_player()`
    - `auth.uid()`から`players.anon_player_id = auth:<uid>`をupsertする内部関数。
  - `is_room_member(room_id)`
    - 待機室の本人判定用RLS helper。
  - `create_friend_room(invite_code, max_players, turn_seconds, cpu_takeover_enabled)`
    - ルームを作成し、ホストをseat 0へ登録する。
    - 同じホストが同じ招待コードで再送した場合は既存seatを返す。
  - `join_friend_room(invite_code)`
    - WAITINGルームへ最小の空席で参加する。
    - 同じユーザーの再送は既存seatを返す。
    - 満室、存在しないルーム、WAITING以外のルームは拒否する。
  - `leave_friend_room(room_id)`
    - WAITING中の参加者を`LEFT`にする。
    - 非参加者、WAITING以外のルームは拒否する。
  - `rooms_select_member` / `room_players_select_member`
    - authenticated参加者だけが待機室情報をSELECTできる。
- `supabase/tests/online_room_lifecycle.sql`
  - 認証必須、ルーム作成、作成再送、参加、参加再送、満室拒否、退出、非参加者退出拒否、再参加を確認。
- `supabase/tests/online_rooms_access.sql`
  - M4-SB-04に合わせ、`rooms` / `room_players`の参加者限定SELECT policyを確認するよう更新。
