## 概要

プレイ時に選択可能な CPU ポリシーのレジストリを追加した。`CpuPolicyId` ユニオン（M2 は `"STANDARD"` の1種類のみ）、UI セレクタ用の `CPU_POLICY_IDS` 一覧、`resolveCpuPolicy(id)` によるルックアップ（未知 id は `Error` を throw）を用意し、Task 5 の `playRound` が座席ごとにポリシーを受け取れる土台を先行整備した。M3 で高度なタイプを追加する際は新規ファイル1つと `REGISTRY` 1行で済む。

`standardPolicy` は最小ヒューリスティック：(1) `goesOut` の手があれば結果の組み合わせが最弱のものを選ぶ、(2) 場が空なら最弱の単体1枚をリードする、(3) 場があれば PASS 以外で結果最弱の手を選ぶ、無ければ PASS。同値候補のタイブレークは「`enumerateLegalPlays` の決定的ソート済み配列に `rng.nextInt(tied.length)`」でシードから再現可能。

`rollThinkDelayMillis(rng)` は再現可能な 600〜1200 の整数を返す（game-core は数値を計算するのみ。実際の待機は後続サブプロジェクトの UI 側）。

## メモ

- M2 出荷は `STANDARD` 1種類のみ。`CpuPolicyId` ユニオン・`CPU_POLICY_IDS`・`resolveCpuPolicy` の per-seat 指定は最初から用意（横断 CPU-006 準拠、M3-EX-03 で高度なタイプを追加）。
- `standardPolicy` はスキルを返さない（`useSkill` を付与しない。スキル運用は M3 送り）。
- 思考待ちは数値のみ返す。実 `sleep` はサブプロジェクト2（UI）で実装。
- 循環 import 対策：`cpuPolicy.ts` は VALUE `standardPolicy` を取り込み `REGISTRY` に入れる。`cpuPolicyStandard.ts` は `cpuPolicy.ts` から `import type` のみ（`CpuDecisionInput` / `CpuPolicy`）でランタイム側の逆辺を作らない。`standardPolicy` はアロー関数の `const`（モジュール読込時に本体は評価されない）。`index.ts` 由来の値（`rankNumber` / `rankStrength`）はヘルパー関数の本体内でのみ参照し、モジュールトップレベルでは使用していない。
- タイブレークは `legalPlays` が `enumerateLegalPlays` で決定的にソート済みであることに依存する。`pickWeakest` は最弱値に一致する候補を安定順で絞り込み `rng.nextInt(len)` で1つ選ぶ。
