## Summary

### 棄権退出（forfeit）— Done

M4-QA-01 ハーネスに `FORFEIT_AT` / `FORFEIT_CLIENT` を追加。指定手番でそのクライアントが
`leave_friend_round(roundId, requested_cpu_takeover=false)` を呼ぶ。ハーネスは以降その席を
飛ばして続行し、「残りプレイヤーの中から勝者が決まる」「棄権者は勝者にならない」を assert。

検証（ローカル）:
- 4人・P2 が turn 8 で棄権 → P1 勝利（33手、`1 forfeit`）。
- 2人・P2 が turn 4 で棄権（残り1人）→ `leave_friend_round` が即 `winner_player_id` を返し
  P1 勝利。
- 5人・障害注入併用・P3 が turn 10 で棄権 → P5 勝利（42手）。

### 60秒自動再接続 — Done（別作業 M4-EX-07）

`onlineRoundStore.test.ts` に「60秒経過で `connection:'offline'` 化しポーリング停止」
「`reconnect()` で全件再取得し復帰」のユニットテスト。

### CPU引き継ぎ — Done

新しい Edge Function `supabase/functions/advance-cpu-turn`:

- POST `{ round_id }`。呼び出し元は対局メンバーであること。
- アクティブ席の `round_players.status` が `CPU_TAKEOVER` なら、`standardPolicy`
  （`@card-game-app/game-core/server`、round id + state_version で決定的にシード）で
  1手選び、`resolveServerPlayRequest` で検証して `commit_friend_play` で確定する。
  CPU 席でなければ `{ ok: true, acted: false }`。
- 冪等: `expected_state_version` ガード + `commit_friend_play` の `p_request_id` で、
  複数クライアントが同時に叩いても1手のみ進む。
- 起動: `onlineRoundStore.poll()` が、アクティブ席が CPU 引き継ぎ席（イベントログの
  `PLAYER_LEFT_CPU_TAKEOVER` から判定）で自分の手番でないときに `advance-cpu-turn` を叩く。
  = 残った誰かがアプリを開いてポーリングしていれば CPU 席が進む（サーバー cron は不要）。

`submit-play` と `advance-cpu-turn` は `supabase/functions/_shared/friendRound.ts` で
スナップショット構築・commit を共有（submit-play を同時にこの共有モジュールへリファクタ）。

検証（ローカル、ハーネス `CPU_TAKEOVER_AT`）:
- 4人・P2 が turn 8 で CPU 引き継ぎ退出 → CPU 席の手番も進み P4 勝利（43手）。
- 5人・障害注入併用・P3 が turn 6 で CPU 引き継ぎ → 完走（P3=CPU が勝利、正常）。
- 棄権退出のリグレッションも通過。

UI の退出ボタンは `leaveRound(true)`（CPU引き継ぎ要求、ルーム設定で無効なら自動的に棄権）。

## Follow-up

- CPU 席の進行は「残ったクライアントのポーリング頼み」。全員がアプリを閉じると
  そのCPU席の手番で停止する（次に誰かが開けば再開）。厳密にはサーバー cron が理想だが
  MVP としては十分。
- `advance-cpu-turn` のシードは state_version ベースで、同一版から複数回呼ぶと同じ手を
  選ぶ（冪等ガードで二重コミットはされないので問題は無い）。
