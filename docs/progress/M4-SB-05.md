# M4-SB-05: シャッフル・配布・先攻決定のサーバー処理を作る

状態: 完了
日付: 2026-09-04

## 概要

M4フレンド対戦で、待機室から1局を開始し、サーバー側でシャッフル、数字カード配布、スキル配布、先攻決定、公開状態作成、開始イベント作成を行えるようにした。

クライアントからデッキ順、スキル順、先攻プレイヤーは受け取らない。`start_friend_round(room_id)`の引数は`room_id`だけで、順序決定はDB側のserver seedとカード・スキルIDから作る。

## 実装

- `supabase/migrations/20260904110000_create_friend_round_start_function.sql`
  - `start_friend_round(room_id)`
    - authenticatedホストだけがWAITINGルームを開始できる。
    - 満室でないルームは開始できない。
    - 既に開始済みの場合、同じroundを返して再送を冪等に扱う。
    - `rounds`、`round_players`、`round_hands`、`round_skills`、`online_round_public_state`、`online_round_events`を1トランザクション内で作る。
    - 数字カード36枚を重複なく全プレイヤーへ配布する。
    - `skill_cards.card_count`から物理スキル枚数を展開し、各プレイヤーへ1枚配布する。
    - 先攻プレイヤーをサーバー側で決定する。
  - `rounds_select_member` / `round_players_select_member`
    - 対局参加者だけが対局情報と席情報をSELECTできる。
- `supabase/tests/online_round_start.sql`
  - ホスト以外の開始拒否、ホスト開始、満室前開始拒否、開始再送の冪等性、数字カード全配布、スキル配布、公開状態、開始イベントを確認。
- `supabase/tests/online_rooms_access.sql`
  - `rounds` / `round_players`の参加者限定SELECT policyを確認するよう更新。
