## 概要

Task 1〜4（`createRng` / `dealRound` / `enumerateLegalPlays` / `resolveCpuPolicy` + `rollThinkDelayMillis`）を束ねる純粋・同期・決定的なヘッドレス対局ループ `playRound(input)` を追加した。

`playRound` は 1 ラウンドを配布し、勝者が出るか安全上限に達するまで手番を回す。各手番で合法手を列挙し、席のポリシーに 1 手選ばせ、`resolvePlay` で適用し、`TurnRecord` を追記して不変条件を検査する。戻り値 `RoundResult` は手番ごとのトレースと `stopReason` を含む。M2-QA-01 の自己対戦ハーネス（Task 6）がこれを 100 回回して「CPU 対局が停滞・不正・カード消失しない」ことを検証する。

## メモ

- **不変条件を毎手検査**（`resolvePlay` 後、違反時は手番 index 付き `Error` を throw）:
  1. 全手札 + `discardPile` + 場のカードの合計 === 36（M2 は Joker 変身なし）
  2. 手札に cardId 重複なし
  3. `state.activePlayerId` が `playerIds` に含まれる
- `NO_PROGRESS` / `MAX_TURNS` は例外ではなく `stopReason`。`stopReason` は「`winnerId` があれば `WINNER`／列挙が空なら `NO_PROGRESS`（CPU 政策を空の合法手で呼ぶ前に break）／手番上限に達したら `MAX_TURNS`」。
- policy が非合法手（`resolvePlay` → `ok: false`）を返したら手番 index・入力・`reason` 付きで throw。バグは seed で再現する（`maxTurns` を上げて誤魔化さない）。
- 決定性 / rng 規律: `rng = createRng(seed)`。`rng.fork()` を「配布 1 回 + 手番ごと 1 回」の固定順で消費するため、手番が増えても配布ストリームはずれない。同一 seed → バイト一致の `RoundResult`。
- 循環 import 対策: `index.ts` は末尾で `roundLoop.js` を re-export する。`roundLoop.ts` が `index.js` から取り込む値（`createRoundState` / `resolvePlay` / `INITIAL_RULESET_VERSION`）は関数本体内でのみ参照し、モジュールトップレベルでは `const DEFAULT_MAX_TURNS = 1000` のみ。
- **ブリーフからの是正**: Step 3 のサンプルコードは `TurnRecord.input` を生の `PlayInput`（`cardIds` を含む）にしていたが、これは横断制約「`TurnRecord` はカード内容を持たない」および Step 1 のテスト（`!JSON.stringify(turn).includes("CARD_NUMBER_")`）と矛盾する。`input` をカード枚数のみ持つ `TurnPlayRecord` に変更した。
- 思考待ちは数値のみ（`rollThinkDelayMillis` で 600〜1200 の整数）。実 `sleep` はサブプロジェクト2（UI）。
