## 概要

対局ループの状態機械。`turnDriver` モジュール（純関数）で `HUMAN_TURN` / `CPU_PENDING` / `ROUND_OVER` を遷移。`humanPlay` は人間手番での手を受けて検証・適用、`cpuStep` は CPU 手番の決定を返す。画面はこの状態を描画し、CPU 思考の実 sleep を行う。`cpuGameStore` がストア状態として `DriverState` を保持し、アクション（`submitPlay` / `pass` / `advanceCpu`）で遷移。

## メモ

- **turnDriver の純粋性** — `initGame` / `humanPlay` / `cpuStep` / `legalPlaysForHuman` は全て純関数。`game-core` の公開 API（`dealRound` / `resolvePlay` / `resolveCpuPolicy` / `rollThinkDelayMillis` / `createRng`）のみ使用。`Date` / `Math.random()` / ストレージ未依存。テスト時に同一 seed で 100% 再現。
- **決定性** — RNG は `createRng(seed)` で1本作り、配布に `fork()` 1 回、手番ごとに `fork()` 1 回（手番 index = `turnLog.length` で消費順序固定）。CPU の同点タイブレークも seed 再現。
- **humanPlay の二重防御** — `ok: false` で理由返却、状態不変。UI は `canSubmit` で「出す」を非活性化しているが、万が一の操作ミスをも排除。
- **cpuStep の決定性** — `resolveCpuPolicy(policyId)({ state, legalPlays, rng })` で決定。thinkMillis は 600～1200（sleep 用）だが、遷移結果は完全決定的。
- **cpuGameStore の職責** — `DriverState` の保持と遷移、`selection` / `legalPlays` のキャッシュ、`result` / `saveStatus` 等の補助状態。ストア設定時に `makeSeed` / `makeId` / `now` / `storage` / `http` を注入（テスト時はフェイク）。
- **ストア設定** — `configureCpuGameStore(deps)` をアプリ起動時（`_layout.tsx`）に1回呼び、モジュール変数に保存。テスト時に `__resetMemo` でリセット。

## テーブル

### turnDriver テスト

| テスト | 対象 | 検証内容 |
| --- | --- | --- |
| 2～6 人完走 | 各人数 | 同一 seed で ROUND_OVER、勝者の手札 0 枚 |
| seed 0～49 試行 | 大規模試行 | 250 試行全て ROUND_OVER、手番 < 500 |
| 決定性（replay） | 同条件再実行 | `deepEqual` で完全一致 |
| humanPlay 不正拒否 | 違法手番 | `ok: false` + 理由、状態不変 |
| cpuStep 合法性 | CPU 決定 | 合法手のみ、thinkMillis 600～1200 |
| legalPlaysForHuman | 導出 | 人間手番時のみ結果 |

### cpuGameStore テスト

| テスト | 対象 | 検証内容 |
| --- | --- | --- |
| 2～6 人完走 | ストア loop | startMatch → selectCard / submitPlay / pass / advanceCpu → ROUND_OVER → finishRound |
| カード保存則 | 毎手番検査 | cardTotal === 36（配布後・人間後・CPU 後） |
| 結果保存 | finishRound | HTTP POST 1 回、二重呼び出しで POST なし |
| 性能チェック | thinkMillis | advanceCpu で次の CPU 待ちミリ秒を返却 |
