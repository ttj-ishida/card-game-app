## 概要

不変の `RoundState` と 1 プレイ入力から次状態を計算する統合関数 `resolvePlay()` を追加した。M1-EX-02〜08 で作った純粋ヘルパー（組み合わせ解析、昼夜強弱、追加・更新、属性ロック、追加封印、革命、Joker、パス・場流し・上がり）を §13.1／付録B の処理順で結線する。関数は純粋で、成功時のみ新しい状態オブジェクトを構築し、不正時は入力状態をそのまま返す。

## インターフェース

- `resolvePlay(state, play): PlayResolution`
  - `play`: `{ kind: "PASS", playerId }` または `{ kind: "PLAY", playerId, cardIds, useSkill?, jokerDeclarations? }`
  - `useSkill`: `"EXTENSION_SEAL" | "REVOLUTION" | "JOKER_TRANSFORM" | "JOKER_CLEAR"`
  - 成功: `{ ok: true, state, outcome }` — `outcome` に `actionKind` / `fieldCleared` / `naturalRevolution` / `dayNightAfter` / `winnerId`
  - 失敗: `{ ok: false, reason, state }` — `state` は入力と同一参照（不変）
- `RoundState` に `consecutivePasses: number`（DB の `consecutive_passes` 相当）と `winnerId: string | null` を追加。`createRoundState()` は既定 `0` / `null`。

## 処理順（付録B）

1. 手番・勝者確定チェック（TURN-001 / WIN-102）
2. 手札にカードが存在するか（二重消費防止）
3. スキル保有・未使用・種別一致チェック（SKILL-002/003/005）
4. 場流し Joker なら場の存在チェック → ロック・封印・場を退避
5. 革命カードは事前反転して合法性判定（REVSKILL-002〜004）
6. `evaluateNumberPlay` / `evaluateJokerTransformPlay` で合法性判定
7. 反映後の手札から `evaluateGoOut` で上がり／禁止上がり判定
8. 追加封印適用・属性ロック判定・昼夜反映・捨て札移動・パス状態リセット（TURN-003 / TURN-004）
9. 数字 0 枚なら勝者確定（WIN-001）

## メモ

- 禁止上がり（WIN-008 / JTR-009）は反映後の実手札から `evaluateGoOut` が単一の権威として判定する。`evaluateJokerTransformPlay` の `remainingNumberCardCount` は `resolvePlay` からは渡さない（手札非依存の組み合わせ判定に限定）。
- 場流し Joker は「場を流す＋同一手番で新しい場をリード」を 1 プレイとして原子的に扱う（JCLR-006〜009）。UI 側の 2 段階タイマー（TIMER-005）は表示層の責務。
- 一度パスしたプレイヤーは、他プレイヤーがカードを出した時点で `PASSED → ACTIVE` に戻す（TURN-004）。
- 棄権（FORFEIT-*）と対局履歴（VIS-005、FIELD-003 の宣言履歴保持）は §19 の通信系・後続マイルストーン範囲。`RoundState` から `status: "OUT"` を除外集計する土台のみ用意した。
- 変化Joker宣言の「場が流れるまで固定」（JTR-003）はアクティブセット上のカードとして保持し、場流し時に捨て札へ移す。
