# M4-SB-08: request_id によるプレイ要求の冪等性

## 状態

完了。

## 実装内容

- `online_play_requests` テーブルを追加し、`round_id` と `request_id` の組み合わせを一意なプレイ要求として記録するようにした。
- `commit_friend_play(...)` に `p_request_id` 付きのオーバーロードを追加した。同じ `round_id/request_id` が再送された場合は、保存済みの結果を返し、カード消費・イベント追加・状態更新を二重実行しない。
- `submit-play` Edge Functionを更新し、共有ルール検証後のコミット時に `request_id` をDB関数へ渡すようにした。
- DBテスト `online_play_idempotency.sql` を追加し、同一リクエストの再送が同じ結果を返し、副作用が1回だけであることを検証した。
